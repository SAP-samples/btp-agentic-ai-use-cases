## Asset Type

- `data-product`: Data product definition. Only if `skills/data-product/SKILL.md` exists; otherwise inform: "Data product asset unavailable - skill not found".

## Important Notes

- The `data-product.json` schema is located at `skills/data-product/assets/data-product.json`. Load it before writing `asset.yaml`.
- The asset folder name and `metadata.name` must be the kebab-case form of the data product Technical Name, appended with `-data-product` (e.g. `SalesOrderAnalytics` → `sales-order-analytics-data-product`).
- The asset folder is created by the `data-product` skill workflow (Step 9) — do **not** create it manually. Call the `setup-solution` skill, then move the existing data-product folder into `assets/`.
- Please follow the `ORD ID Construction` and `asset.yaml` rules strictly
- After moving the folder into `assets/`, verify the solution's file tracking reflects the move. A filesystem move does **not** automatically update the solution's tracked file list — both must be reconciled.

## Required Folder Structure

```
assets/
└── <name>-data-product/
    ├── work/
    │   ├── aggregated_csn.json
    │   ├── csn_graph.json
    │   └── input-dp-ams-policy.json
    ├── asset.yaml
    ├── <dp-name>.dpd     # DPD interop file (generated by jl data-product generate-interop)
    └── transformation.cds
```

## ORD ID Construction

The following ORD ID pattern must be followed for Data Product Assets:

```plain
c.bdc.<solution-id-encoded>:dataProduct:<data-product-name>:v<version>
```

Following the rules below:

| Segment           | Rule                                                                                                                    |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `c.bdc.<solution-id-encoded>`  | Fixed namespace prefix for customer-created assets. Please refer to `.ddp_metadata.json` for its value                                                                     |
| `dataProduct`     | Fixed ORD resource type.                                                                                                |
| `<data-product-name>`    | `name` from the asset's `DPD Interop` header section. Must not contain dots; underscores allowed, hyphens are preferred. |
| `v1`              | Fixed at `v1` for MVP; never incremented by customer or platform.                                                       |

**Example:**

```plain
c.bdc.a76lgqi1lc9i8a6ppfetl7gck:dataProduct:SalesOrderAnalytics:v1
```

## Example: Data Product Asset

Ensure that your asset.yaml doesn't contain any additional fields other than the ones given in the example below

```yaml
apiVersion: asset.sap/v1
kind: Asset

metadata:
  name: sales-order-analytics-data-product
  version: 1.0.0

type: data-product

sourceRoot: "."

provides:
  data:
    name: sales-order-analytics-data-product
    kind: data-product
    ordId: c.bdc.a76lgqi1lc9i8a6ppfetl7gck:dataProduct:SalesOrderAnalytics:v1
    format: interop

requires: # Should contain the output ports of the input data products
  - name: sales-order
    kind: apiResource
    ordId: sap.s4com:apiResource:SalesOrder:v1
  - name: cost-center
    kind: apiResource
    ordId: sap.s4com:apiResource:CostCenter:v1

production:
  definitionFile: SalesOrderAnalytics.dpd
```

## Availability Check

- If the user requests a data product and `skills/data-product/SKILL.md` exists: proceed with data product asset creation.
- If `skills/data-product/SKILL.md` is missing: inform the user — "Data product asset unavailable - skill not found."
